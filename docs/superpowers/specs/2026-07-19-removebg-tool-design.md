# removebg 툴 설계 문서

- **작성일**: 2026-07-19
- **저장소**: https://github.com/blackrabbitDeveloper/removebg
- **배포 URL(예정)**: https://blackrabbitdeveloper.github.io/removebg/

## 1. 목적

GitHub Pages(정적 호스팅)에서 동작하는, 이미지 배경 제거 웹 툴.
이미지를 업로드하면 **브라우저 안에서** AI 모델로 배경을 제거하여 투명 PNG로 저장한다.

## 2. 핵심 제약과 결정

| 항목 | 결정 | 이유 |
|------|------|------|
| 실행 위치 | **완전 클라이언트 사이드** | GitHub Pages는 서버가 없음. 외부 API는 키 노출 위험 |
| 배경 제거 엔진 | **`@imgly/background-removal`** (브라우저 내 AI 모델) | 복잡한 사진도 고품질, 무료, 오프라인, 이미지가 서버로 안 나감 |
| 빌드 | **무빌드** (CDN ESM import) | 번들러/Action 불필요, push하면 바로 동작, 유지보수 단순 |
| 기능 범위 | 기본(업로드→제거→PNG 다운로드) + **Before/After 슬라이더** | 사용자 선택 |
| UI 언어 | **한국어** | 사용자 선택 |
| 모델 | `isnet_fp16` (품질/속도 균형) | 다운로드 크기와 품질의 절충. 코드에서 교체 가능 |

## 3. 아키텍처

무빌드 정적 SPA. 저장소 루트에 배치하여 Pages로 서빙한다.

```
removebg/
├── index.html          # 레이아웃 (헤더 · 업로드 영역 · 미리보기/슬라이더 · 액션 버튼)
├── css/style.css       # 스타일 (다크 테마, 반응형, 체커보드 투명 배경)
├── js/
│   ├── main.js         # 앱 오케스트레이션: 상태·이벤트 연결
│   ├── bgremover.js    # @imgly removeBackground 래퍼 + 진행률 콜백
│   └── compare.js      # Before/After 슬라이더 컴포넌트
├── assets/             # 파비콘 · 아이콘 · 샘플 이미지
├── .nojekyll           # Pages가 파일을 그대로 서빙(Jekyll 우회)
├── .gitignore
└── README.md
```

### 모듈 경계 (단일 책임)

- **`bgremover.js`** — 입력: 이미지 Blob/URL + 진행률 콜백. 출력: 투명 PNG Blob.
  `@imgly` 라이브러리 세부사항을 캡슐화. 앱의 나머지는 이 인터페이스만 안다.
- **`compare.js`** — 입력: 원본 이미지 URL + 결과 이미지 URL. 슬라이더 DOM을 만들고
  드래그로 두 이미지를 비교 노출. 배경 제거 로직을 모른다.
- **`main.js`** — DOM·이벤트·상태를 조율. 위 두 모듈을 사용해 흐름을 구성.

## 4. 데이터 플로우

1. 사용자가 이미지 업로드 (파일 선택 **또는** 드래그&드롭, 붙여넣기 지원 고려)
2. 원본 미리보기 표시, "배경 제거 중… NN%" 진행률 노출
3. `bgremover.removeBg(blob, onProgress)` 호출 → 투명 PNG Blob 반환
4. 결과를 체커보드(투명 배경) 위에 렌더
5. Before/After 슬라이더로 원본↔결과 비교
6. "PNG 다운로드" 버튼으로 저장 (파일명: `원본이름-removebg.png`)
7. "다시 하기"로 새 이미지 처리

## 5. UI/UX

- 다크 테마, 카드형 중앙 레이아웃, 모바일 반응형
- 상태별 화면: (a) 초기 업로드 대기 → (b) 처리 중(진행률) → (c) 결과/비교 → (d) 에러
- 투명 영역은 체커보드 패턴으로 시각화
- 개인정보 안내 문구: "이미지는 서버로 전송되지 않고 브라우저에서만 처리됩니다."
- 첫 실행 시 모델 다운로드(수십 MB)로 시간이 걸릴 수 있음을 진행률과 안내 문구로 표시

## 6. 에러 처리 (모두 한국어 메시지)

| 상황 | 처리 |
|------|------|
| 이미지가 아닌 파일 | "이미지 파일만 업로드할 수 있어요" |
| 파일 과대 (예: > 25MB) | "이미지가 너무 커요. 더 작은 이미지를 사용해 주세요" |
| 모델/네트워크 로드 실패 | "모델을 불러오지 못했어요. 네트워크 확인 후 다시 시도해 주세요" + 재시도 버튼 |
| 처리 중 예외 | 콘솔 로깅 + 사용자엔 일반 실패 메시지 + 재시도 |

## 11. 브러시 편집 (v2 추가)

AI 결과가 완벽하지 않을 때 수동으로 보정하는 브러시 편집기. (사용자 선택: 편집 위주 + 비교 버튼 / Undo+Redo / 강도 슬라이더)

### 데이터 모델 — 알파 마스크
- `원본 RGB`(불변) + `마스크`(픽셀별 투명도 0~255)를 분리 유지.
- 초기 마스크 = **AI 결과 PNG의 알파 채널**.
- 화면/저장 = 원본을 그린 뒤 `destination-in`으로 마스크 적용. 투명 영역엔 체커보드가 비침.
- **복원 브러시**: 마스크에 흰 스탬프(`source-over`, 알파 증가) → 원본 복귀.
- **지우개 브러시**: 마스크에 `destination-out` 스탬프(알파 감소) → 투명.
- **강도**: 방사형 그라디언트 스탬프. 0=부드러운 페더링 ~ 100=선명한 경계.
- 연속 획: 이전 점~현재 점을 보간해 스탬프 → 빠른 드로잉에도 끊김 없음.

### Undo/Redo
- 획(pointerdown→up) 단위로 마스크 `ImageData` 스냅샷을 undo 스택에 push, 새 획 시 redo 스택 clear.
- 메모리 보호: 스냅샷 개수 = `clamp(floor(64MB / (W*H*4)), 3, 20)`.
- 버튼 활성/비활성은 스택 길이에 연동.

### 화면 구성
- 결과 시 `#result`가 편집기. 편집 캔버스(체커보드 배경) + 브러시 크기만 한 원형 커서.
- 툴바: (복원)(지우기) 세그먼트, 크기 슬라이더, 강도 슬라이더, 되돌리기/다시실행, '원본과 비교'.
- '원본과 비교' → 편집 캔버스 숨기고 `원본 vs 현재 편집본` 슬라이더(`compare.js` 재사용) 표시, 다시 누르면 복귀.
- 다운로드: 매 획 후 편집본 Blob을 만들어 다운로드 링크 갱신.

### 모듈
- 신규 `js/editor.js` — 캔버스/마스크/undo·redo/합성/커서. 입력: mount, 원본 이미지, AI 결과 이미지. 출력: `getBlob()`, 상태 콜백(undo/redo 가능 여부, blob 갱신).
- `main.js` — 결과 시 `mountEditor` 사용, 툴바 이벤트·비교 토글 연결.
- `compare.js` — 재사용(비교 뷰).

### 좌표/성능
- 캔버스 내부 해상도 = 원본 해상도(품질 유지), CSS로 컨테이너 폭에 맞춤.
- 포인터 좌표 → 캔버스 픽셀 좌표 변환(rect 스케일). 브러시 크기는 표시 px 기준 입력 후 자연 px로 변환.
- 합성 재그리기는 `requestAnimationFrame`으로 throttle.

### 검증(v2)
- 헤드리스 Chrome로 결과 생성 후, 편집 캔버스에 지우개 획을 그어 **투명 픽셀 증가**, 복원 획을 그어 **불투명 픽셀 증가** 확인. Undo가 이전 상태로 되돌리는지, 다운로드 Blob이 편집을 반영하는지 확인.
